## 0. 一页结论

**主干顺序**：先冻契约 → 证明确定性 → 做手感闭环 → 最后堆内容。方案结语说"纯 TS 的确定性模拟核心是全案唯一的架构赌注"，所以第一周围绕它展开；Cocos 侧同时只证明一件事：空工程能在真机上预览。

**本计划新拍板的 10 件事**（理由见第 9 章）：

1. **确定性门禁第 1 天就在本机跑**：Node arm64（V8）、Node x86_64（Rosetta 下的 V8，代表服务端）、Bun（JSC JIT）、`jsc --useJIT=false`（JSC 解释器，近似 iOS 标准模式）。昨天已实测：RK4 飞行 2,000 次，哈希在这些引擎上全部一致；`Math.sin/exp/pow/atan2` 三方都不一致。
2. **G0 的真机确定性不依赖 Cocos**：用一个空白微信小游戏工程（`tools/wx-selftest`，`game.js` 加载 `sim.js`、跑内核语料、打印哈希），测试号就能预览，手机到货当天就能测。Cocos 的 Bench 只回答性能与 3D 问题。
3. **模拟核心发布成单一产物**：`packages/sim` 打成一个 `sim.js`，同一份代码进 Cocos（插件脚本）、Node 服务端、四引擎门禁和 wx-selftest；`simVer` = 该文件的 FNV 哈希。
4. **击球反解改为离线查表，力度 = α 倍率**：`tools/tablegen` 用模拟核心自己的 RK4 生成表（8 击球 × 15 高度 × 53 距离，约 25 KB），运行时只做双线性插值。力度只乘时间缩放 α，所以到达时间 ∝ 1/α、过网速度 ∝ α、落点不变，正好是方案 §2.2"力度映射到到达时间与过网速度，而不是射程"。
5. **输入按"触摸那一帧所显示的模拟时间"打戳**：显示时间 ≤ 模拟时间 ≤ 真实时间，所以接触点就是玩家当时看到的球的位置，渲染滞后不需要任何调参常数；延迟校准滑杆是唯一的偏移。
6. **hit-stop 是模拟状态**：冻结期间物理与走位停止，AI 感知与反应计时照走；赢分与赛点的冻结在死球时触发，不在接触时。
7. **影响模拟的一切都进 MatchCfg 或 contentHash**：装备、属性、新手窗口、A/B 组写进回放头；远程 JSON 只放开关。场馆只改外观，不改终端速度。
8. **前 6 周只开 2–3 条并行轨道**：SIM（一个代理按序做物理 → 规则 → AI）、CLIENT（你 + 代理做 Cocos），10-21 起加 PLAY（playground）；G1 之后才扩到 4 轨。流程从轻到重：先只有 `bun run merge <轨>`，11-18 才加白名单检查与 CCR。
9. **Cocos：静态环境在 boot.scene 里手工搭，动态角色与 UI 在 TS 里建**；代理永不碰 `.scene/.prefab/.meta`。
10. **P0/P1 后端走微信云托管 `callContainer`**：官方写明用云托管可不配置通讯域名，开发版/体验版开调试也不校验域名，所以域名 ICP 备案退出开发关键路径（仍在第一周提交，因为广告回调与 P2 可能需要它）。

**核查中发现的两处方案自身问题**（需要改闸门，见第 11 章）：
- **体验成员上限装不下 G2 的 100 人**：企业未认证 30、已认证未发布 60（取自小程序文档，推定适用于小游戏），而方案 G2 要求 ≥100 名外部玩家。
- **01-12 验不了真实的广告服务端校验**：激励视频的服务端奖励回调只能在流量主后台配置，而方案自己写流量主在软启动后、累计 UV >500 才开通。01-12 只能用模拟模块验收，第一次真实验证在软启动第 2 周。

**关键路径（★）**：真机预览打通 10-10 → 契约 v1 冻结 10-11 → G0 10-20 → 真机滑动能打出一拍 10-27 → 骨骼/动画契约随外包需求包发出 11-03 → G1 11-17 → 备案截图构建 11-28 → 备案提交 12-01（最迟 12-15）→ 范围冻结 12-21 → 外包终版动画 01-05 → 体验版 01-12 → G2 02-23 → 终版提审 03-09 → 软启动 03-16 → 流量主开通并验证回调（软启动第 2 周）。

## 1. 已验证的事实（会改变构建顺序的部分）

### 1.1 本机确定性实测（2026-10-07）

脚本：2,000 次随机击球，二次阻力 RK4（1/60 s 步长）、xorshift32、对 Float64 位模式做 FNV-1a，每 30 步混入一次完整状态。

| 引擎 | dsqrt 路径 | Math.sqrt 路径 | sin/exp/pow/atan2 |
|---|---|---|---|
| Node 24 arm64（V8） | 3e34ca | e0082e4a | 17fb5a11 |
| Node 24 x86_64（Rosetta，V8） | 3e34ca | e0082e4a | dd072c50 |
| Bun 1.4（JSC JIT） | 3e34ca | e0082e4a | 4c8cf200 |
| jsc（JSC JIT） | 3e34ca | e0082e4a | 4c8cf200 |
| jsc --useJIT=false（JSC 解释器） | 3e34ca | e0082e4a | 4c8cf200 |

- 四则运算加 `dsqrt` 或 `Math.sqrt`，在五种引擎/架构组合下逐位一致。方案 §3.3 的"受限双精度"路线成立，Q16.16 大概率用不上（仍以 G0 真机为准）。
- 超越函数连同一个 V8 在 arm64 与 x64 上都不一致：禁用清单必须执行，并且要扫**构建产物**。
- `dsqrt` 与 `Math.sqrt` 在约 25% 的输入上差 1 ulp。两者各自确定，但只能用一个；本计划沿用方案的 `dsqrt`，模拟核心内禁用 `Math.sqrt`。
- 审查时追加的数值实验：表与 α 无关的结论在 1/60 s 步长下成立（α 0.4–1.5 落点偏移 <1 mm），**前提是落地、过网、到达击球高度这些事件在子步内做线性插值**；不插值时误差可达 21 cm。终端速度 6.4/6.6 对 6.5 会让高远落点偏移 ±30 cm。
- 本机已有：Node v24.17、Bun 1.4.0（`~/.bun/bin/bun`）、jsc（不在 PATH 上，路径 `/System/Library/Frameworks/JavaScriptCore.framework/Versions/Current/Helpers/jsc`）、python3 3.11、微信开发者工具 2.02.2608070（含 `cli` 与 `wechatide`）。**Cocos Creator 尚未安装。**

### 2.2 模拟核心的发布与禁令

- `bun run sim:build`：esbuild 把 `packages/sim/src/index.ts` 打成 `dist/sim.js`（IIFE，ES2017，不压缩）；文件末尾显式赋值 `(typeof GameGlobal !== 'undefined' ? GameGlobal : globalThis).BadmintonSim = api`（不用 esbuild 的 `--global-name`，它产生的顶层 `var` 在微信、Cocos、Node、Bun 里都不会成为全局）；`tsc --emitDeclarationOnly` 生成 `sim.d.ts`（声明全局变量）；写 `dist/sim.version`（文件字节的 FNV-1a）。
- 分发：复制到 `client/assets/plugins/sim.js`（Cocos"导入为插件"，`.meta` 只由人在编辑器里设一次）与 `tools/wx-selftest/sim.js`；服务端与门禁直接加载 `dist/sim.js`。每个门禁引擎用同一种方式加载。
- **发布后三项检查**（替代"整文件逐字节比对"，后者因 Creator 插入适配代码必然失败）：① `dist/sim.js` 作为连续子串出现在 Cocos 构建产物的插件文件里；② `sim:scan` 在构建产物上通过；③ 真机 SelfTest 哈希 = Node 哈希（上传后微信会编译 `.js`，只能做行为检查）。
- `bun run sim:scan`：在 `dist/sim.js` 与构建产物上，拒绝 `Math.` 除 `abs/min/max/floor/ceil/trunc/round/sign/imul/fround` 以外的一切调用、`**`、`Date`、`Math.random`、`Math.sqrt`。
- 源码层 ESLint 规则同上；模拟核心不得引用 `cc`、`wx`、DOM、Node 内置模块；不用 `enum/namespace`，类型用 `import type`。
- 热路径不分配：`step()` 内禁止 `new`、数组字面量与闭包。
- **事件插值**：落地、过网平面高度、到达击球高度这三类事件一律在 1/60 s 子步内做线性插值，由 `events.ts` 里同一个函数提供，tablegen 与模拟共用。

### 2.3 契约（10-09 起草，10-11 冻结 v1；之后改动 bump 版本并在 `packages/contracts/CHANGELOG.md` 记一行）

```ts
// packages/contracts/api.ts
export const SIM_HZ = 30;
export const U_PER_TICK = 1000;          // 1u = 1/30000 s：tick 与 ms 都是整数
export const U_PER_MS = 30;

export interface InputEvent {            // 全整数；回放与 P2 线上同一 16 字节布局
  tick: number;    // u32 被模拟"消费"的 tick（最早一个尚未步进的 tick）
  offMs: number;   // i8 −128..+127：打戳时间相对该 tick 起点的毫秒，本地输入恒 ≤ 0；早于 −128 ms 的输入丢弃并计数
  player: 0 | 1;
  kind: number;    // DOWN | RELEASE | PREMOVE | CANCEL（与 player 共用 1 字节）
  tx: number; tz: number;   // i16 cm：触点投影到球场坐标（预判走位目标 / 瞄准落点）
  dx: number; dy: number;   // i16 ‰屏宽：滑动向量（屏幕空间，用于手势分类）
  durMs: number;            // u16 按下到松手
}

// packages/contracts/match-cfg.ts —— 原样写进回放头与快照 I32 头
export interface MatchCfg {
  rulesId: number;          // QUICK7 | RANKED11 | INTL15 | TUTORIAL5
  seed: number;             // 挑战与周挑战由服务端下发；单机本地生成
  venueId: number;          // 纯外观，不进物理
  ddaEnabled: 0 | 1;        // 排位与好友约战强制 0
  staminaEnabled: 0 | 1;    // 体力 A/B
  abGroup: number;
  players: [PlayerCfg, PlayerCfg];
}
export interface PlayerCfg {
  kind: 0 | 1;                    // 0 人，1 AI
  aiLevel: number;                // 1..10，人为 0
  windowScalePermille: number;    // 默认 1000；新手 1200–1300（方案 §2.3）
  alphaScalePermille: number;     // 装备与属性只作用于这四项（不碰 v0 与 v_t，查表不受影响）
  scatterScalePermille: number;
  runSpeedPermille: number;
  staminaMaxPermille: number;
  inputOffsetMs: number;          // 延迟校准滑杆值，仅作审计：客户端已在量化前扣除
}

export interface Sim {
  step(inputs: ArrayLike<InputEvent>): void;            // 恰好一个 tick；热路径零分配；AI 在内部决策
  save(dst: Snapshot): void; load(src: Snapshot): void;
  hash(): number;                                       // FNV-1a over i32 + f64 位
  drainEvents(out: Int32Array): number;                 // LAUNCH CONTACT JUDGE HITSTOP BOUNCE NET OUT DEADBALL POINT GAME_END（打包）
  predictContact(p: 0 | 1, out: Float64Array): boolean; // 落点阴影、收缩环、AI 感知、音效预调度共用
  readonly view: Float64Array;                          // 渲染只读：位置、动作意图（蓄力至 tContact）、环相位、高度带提示
}
export declare function createSim(cfg: MatchCfg, content: ContentBundle, tables: ShotTables): Sim;
```

### 2.4 时间、接触与 hit-stop 语义（写进 T2 的性质测试）

**打戳**：渲染用标准固定步长加插值，模拟时间永不超前于真实时间。客户端在每帧记下"这一帧显示的模拟时间"；触摸按它落在的那一帧所显示的模拟时间打戳（加帧内偏移），再减去延迟校准值后量化。因为显示时间 ≤ 模拟时间，接触点就是玩家当时看到的球的位置，渲染滞后不需要调参常数。输入在最早一个尚未步进的 tick 消费，所以本地输入的 `offMs` 恒 ≤ 0（正值只出现在 P2 的远端输入里）。hit-stop 冻结期间画面静止，此时落下的触摸按冻结所在 tick 的起点打戳。

**接触**：
- 理想时刻 t* = 球（在子步内插值）到达接收方击球高度的时刻，只取整一次到 u。
- **可达性与高度带在 t* 判定**，用角色在 t* 时的位置。晚松手只改变判定等级与发射点，不扩大可达范围（否则"够不着就晚点松手"会成为最优策略：+160 ms 能让杀球可达半径从 1.93 m 涨到 2.81 m）。
- 误差 e = 打戳时刻 − t*：|e| ≤ 160 ms 进入判定；e < −160 ms 为提前空挥（Miss）；e > +160 ms 为 Miss。
- 接触时刻 t_c = max(t*, 打戳时刻)；发射点 = 来球路径在 t_c 的位置（子步插值）。低于 0.4 m 判 Miss。
- 回球：按（击球类型、发射点高度、到瞄准落点的水平距离）查表得发射斜率，α = α_击球 × 力度倍率 × 判定速度修正 × `alphaScalePermille`；模拟从 t_c 快进到当前 tick。

**hit-stop**：
- 冻结 tick 数：Perfect 2、杀球/赢分 3、赛点 4（30 Hz 下 50 ms 无法表示）；方案的 A/B（3 帧对 6 帧）落为 2 对 3 tick。
- 冻结期间物理与走位停止，**AI 感知与反应计时照走**，人和 AI 都拿到同样的额外时间；tick 计数照常递增。
- Perfect 的冻结在接触时触发（判定已知）；赢分与赛点的冻结在 DEADBALL/POINT 时触发（接触时还不知道是不是赢分，提前冻结等于泄题）。
- `calib` 的可达半径表用 T + 冻结时长计算；A/B 在相同 AI 档位下进行，偏好与胜率一起报告。
- 慢动作只在死球后播（纯视图）。新手引导第 3 步的"慢动作提示"（方案 §2.5）做成模拟内的时间膨胀，只在单机教学里启用，判定窗口按模拟时间算。

**重切时点**：G0、G1、12-21、01-12，用 `/dispatch` 重新派单。派单形式沿用你的约定：每轨一个 worktree（`.worktrees/task-tN`，基线钉主干具体 sha），派单落盘 `review/paste-TN.md`，一行 `claude-fleet --repo <仓库路径> t1..tN` 开齐；派单第 1 步让子会话 Read 守卫脚本，确认 hook 已挂上。Cocos 编辑器只开 CLIENT 轨的 worktree；主干的构建车道在合并后构建（首次需导入一次 `library/`）。

### 4.3 让 Cocos 客户端可以由 AI 编写

1. **静态环境手工搭，动态内容代码建**：boot.scene 里由你在编辑器搭相机、灯光、平面阴影、球场与一个挂 `Bootstrap` 的节点（这也是官方教程的路数，新手上手最快）；角色、球、特效与 UI 由 TS 在运行时创建。`Bootstrap.ts.meta` 的 uuid 生成后永不改。
2. 资源只按路径加载，不靠序列化引用：`match`、`ui`、`audio`、`venue2`、`cosmetics` 设为 Asset Bundle（小游戏分包），bundle 标记与功能裁剪由你在编辑器里设；`tools/assetpaths` 在每次导入后生成 `scripts/gen/assetPaths.ts`，代理只引用生成的常量。
3. 材质在代码里由一个导入的卡通 `.effect` 实例化；代理可以改已有的 `.effect` 文本，不能新建资源文件。
4. UI 是数据：界面写成 TS 规格对象，由约 10 个控件（Panel/Label/Button/Bar/List/Toast/Icon/Tab/Modal/SafeArea）渲染。Label 默认用 CHAR 缓存模式，规避 3.8.8 社区报告的"Label 不显示"问题（Spike 验证）。
5. 构建只在构建车道上串行跑：需要 GUI 会话，而且每个 worktree 都会重建 `library/`。代理验收只跑 `tsc` 与单测。
6. 触摸垫片（若需要）放在构建模板的 `game.js` 里、引擎加载之前，因为引擎初始化时复制 `wx`。
7. P0 不用 cocos-mcp-server。

### 4.4 只能由人做的事

设备回归与体验版上传；所有手感判断（滑动阈值、窗口、hit-stop、镜头、AI 难度：代理出建议，你拍板）；编辑器里的场景搭建、资源导入、ASTC 预设、bundle 与功能裁剪；美术方向与外包验收（`artcheck` 只做初筛）；MP 后台（隐私指引、适龄提示、广告位、体验成员、备案材料、安全风控申请、最低基础库）；合并与契约变更。

## 9. 对方案的偏离

### 9.1 改变方案结论、闸门或排期的（请先读这张）

| # | 内容 | 理由 | 方案 § |
|---|---|---|---|
| 1 | G0 改为"内核语料在真机上的确定性 + 罐装轨迹驱动的 Bench"；对局级确定性与 1,000 局移到 G1；Spike 5 改为 1 小时不阻塞探测，Spike 8 改由 01-12 版本的 `net.rtt` 遥测收集，Spike 7 跳过 | 对局要等规则、判定、AI 全部完成，10-20 做不到；5、7、8 只服务于 G3 之后的 P2 | 0.4、3.9 |
